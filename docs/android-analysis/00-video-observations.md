## 1. 전체 인상

| 항목 | 값 |
| -- | -- |
| 배경 | 순백에 가까운 흰색. 카드/시트만 흰색 위에 그림자로 뜬다 |
| 주색 | 인디고~퍼플 계열 한 가지. CTA 버튼·선택 상태·강조 텍스트가 전부 이 색 |
| 라운드 | 버튼·카드 모두 크게 둥글다. 버튼은 거의 pill에 가까운 12~16px대 |
| 폰트 | Pretendard. 제목은 굵게(700), 본문은 400~500 |
| 여백 | 화면 좌우 패딩이 넉넉하다(폭의 5~6%). 섹션 사이 간격이 크다 |
| 상단 | 대부분 `< 제목 우측액션` 형태의 앱바. 좌측 뒤로가기, 우측에 `편집` 같은 텍스트 액션 |
| 하단 | 주 CTA가 화면 하단에 고정된 풀폭 버튼(Bottom CTA Bar) |

**웹 포팅 관점**: 그림자를 거의 쓰지 않고 색 대비와 여백으로 층을 나눈다. CSS로 재현하기 쉽다.

## 3. 화면별 실측 관찰

### 3.1 온보딩 (f002 ~ f008)

```
[진행 점 4개]                    건너뛰기
말하기 어려웠던 증상,
함께 준비해요.

아픈 곳을 짚고, 증상을 말해 주세요.
진료 전에 보여줄 카드부터
진료 후 기록까지 함께 정리해요.

        [일러스트]

[        다음        ]
```

- 상단 좌측에 **점 4개 progress** (현재만 길쭉한 pill, 나머지는 원). 우측에 `건너뛰기`
- 제목은 2줄, 굵게. 본문은 3줄, 회색
- 일러스트는 연보라 원형 배경 + 흰색 선화 캐릭터 + 체크리스트 보드
- 마지막 장 버튼만 `시작하기`

**웹 대체**: 일러스트 4종은 원본 리소스를 확보하거나 동일 톤의 SVG로 새로 그려야 한다.
원본은 `res/drawable`에 있는지 확인 필요 (영상만으로는 이름을 알 수 없음).

### 3.4 인체도 부위 선택 1/4 (f021)

```
<           기록
(...상단 안내문 스크롤 영역...)
[  앞면  ][  뒷면  ]           ← Segmented Control
(전신) (피부)              목록에서 고르기

┌──────────────────────┐
│    [3D 회색 인체 모델]   │
│    검은 점 9~10개 오버레이 │
└──────────────────────┘

[        다음        ]  ← 부위 선택 전 비활성(회색)
```

**중요**: 인체도는 **실제 3D 렌더 메시**다. 회색 무광 인체 모델 위에 **검은 원형 점**이
부위 마커로 얹혀 있다. 확인된 점 위치(대략): 머리, 목/가슴 상부, 가슴, 왼팔, 오른팔,
복부, 왼무릎, 오른무릎.

- 상단에 `앞면 / 뒷면` 세그먼티드 컨트롤
- 그 아래 `전신` `피부` 칩 + 우측 `목록에서 고르기` 텍스트 버튼
- 인체도 영역은 밝은 회색 배경의 라운드 박스
- 부위를 고르면 **세부 구역 선택**이 뜨고(예: 배 → 오른쪽 윗배(명치)), 세부까지 골라야
  `다음`이 활성화된다 (데모 기록 PROGRESS.md에 명시)

**정정** — 처음에 "3D를 재현할 필요가 없다"고 적었는데 **틀렸다.**

`BodyMapUiState.kt` 의 `val byMap3d: Boolean = true` 가 기본값이라, 앱은 **실시간 3D를
기본으로 쓴다.** Filament 로 `assets/body3d/body.glb`(514KB · Draco 압축)를 그리고,
끌어서 돌리고 오므려서 확대한다(`body_map_3d_description`).

아래 webp 9장은 **3D 를 쓰지 않는 경로(ANCHOR/ZONE)의 이미지**다. 둘 다 앱에 들어 있고
기본은 3D 다.

| 자산 | 쓰임 |
| -- | -- |
| `assets/body3d/body.glb` | 실시간 3D 인체도 (기본) |
| `assets/body3d/body_collision.bin` | 짚은 자리 판정용 축소 메시(4만 6천 삼각형) |
| `drawable-nodpi/bodymap_front.webp` · `_back` | 비3D 경로 · 전신 앞/뒤 |
| `drawable-nodpi/bodymap_{head,neck,chest,abdomen,arm,leg,lower_back_hip}.webp` | 비3D 경로 · 부위 확대 |

**웹앱 구현**: three.js 로 **같은 glb** 를 그린다. 좌표(`BodyMap3dGeometry.kt` 의 구역 점
46개 · 앵커 점 9개 · 카메라 프레임 7개)와 카메라 규격(FOV 28° · 홈 거리 2.3 · 확대 범위
0.45~2.6 · 판정 문턱 신장의 10%)도 앱 값을 그대로 옮겼다. WebGL 을 못 쓰는 환경에서는
앱의 비3D 경로와 같이 webp + 좌표 핫스팟으로 되돌린다.

원본 webp 는 베이지색이고, 앱 화면의 회색 톤은 런타임 색 처리다.

### 3.5 증상 문답 2/4 (f022 ~ f034)

```
<           기록
증상 정리                        2 / 4
[━━][━━][──][──]                 ← 4구간 분절 바

짚은 부위  (오른쪽 윗배(명치))     ← 선택 부위 칩

AI
오른쪽 윗배(명치) 쪽이 어떻게 불편하신지 편하게
말씀해 주세요.
                    ┌───────────────┐
                    │ 명치가 불편해요.  │  ← 사용자 말풍선
                    └───────────────┘
AI
언제부터 그러셨어요? ...

[ 메시지 입력            🎤  ↑ ]
```

- **AI 말풍선은 배경 없음.** `AI` 라벨(작은 회색) 아래 검은 본문 텍스트만. 말풍선 테두리 없음
- **사용자 말풍선만** 연보라 배경 + 라운드, 우측 정렬
- 입력창은 하단 고정. 라운드 풀폭, 우측에 🎤(마이크)와 ↑(전송) 아이콘
- 포커스되면 입력창 테두리가 주색으로
- 마지막 턴(7턴) 뒤 AI가 정리 멘트를 하고 **`다음` 버튼이 입력창 위에 나타난다** (f033)
  - 문구: `말씀해 주신 내용을 정리해서 진료 때 보실 수 있게 준비했어요.`

### 3.6 통증 강도 3/4

프레임에 선명하게 잡히지 않음 → 소스 확인 필요. 큐카드 기준 슬라이더 정지점 5단계,
3번째가 `꽤 아파요`. 카드에서는 `3 꽤 아파요 / NRS 5~6`으로 표기된다(f056에서 확인).

- 상단 앱바 우측 `편집`

**주의**: 데모에서 카드에 **묻고 싶은 것(질문) 영역이 누락**되어 있었다 (PROGRESS.md 명시).
큐카드 기대 산출물에는 있다. **웹앱에서는 질문 블록을 반드시 넣는 것이 맞다.**

- 선택된 날짜는 **주색 라운드 사각(squircle)** 배경 + 흰 숫자, 그 아래 작은 점
- 범례가 그리드 하단에: `● 기록 있음` `○ 예정` — **채운 점 / 빈 점**으로 구분
- 바텀시트는 흰 배경 + 상단 핸들 바. 뒤 화면은 어둡게 처리(스크림)
- 시트 진입 시 자동으로 열린다 (PROGRESS.md: "진입 시 15일 바텀시트가 자동으로 열림")

- 카드 선택은 **체크박스 카드**(선택 시 주색 테두리 + 체크)
- 할 일은 체크박스 + 인라인 입력 + 우측 ✕ 삭제

- 다음 일정 카드만 **주색 채움 + 흰 글씨**로 시선을 끈다
- D-day pill은 흰 배경 + 주색 글씨
